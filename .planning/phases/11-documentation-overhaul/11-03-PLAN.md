**Section 1: Introduction** (~5 lines)
Brief intro: rbmi's MI pipeline produces several intermediate objects (draws, imputation, pool). rbmiUtils v0.3.0 adds tools to inspect these objects and extract diagnostic metadata.

**Section 2: Setup** (eval=TRUE code chunk)
Load libraries (rbmiUtils, rbmi, dplyr), load ADMI data, set up vars and method (use method_bayes with n_samples=100, warmup=200, thin=5 -- same as generate-doc-images.R), run the full pipeline: analyse_mi_data -> pool. This setup chunk is needed for the pool_to_ard section.

**Section 3: Inspecting Draws with describe_draws()** (eval=FALSE)
- Explain that describe_draws() extracts structured metadata from draws objects
- Show an `eval=FALSE` code block demonstrating: `draws_obj <- draws(data, vars, method)` then `desc <- describe_draws(draws_obj)` then `print(desc)`
- Include hand-formatted example output as a verbatim code block showing what the cli print method displays (method, formula, samples, failures, convergence diagnostics)
- Explain the returned fields: method, method_class, formula, n_samples, n_failures, convergence (for Bayesian: ess_bulk, rhat)
- Note: eval=FALSE because draws() requires MCMC which is slow in vignette builds

**Section 4: Inspecting Imputations with describe_imputation()** (eval=FALSE)
- Explain that describe_imputation() extracts imputation metadata
- Show `eval=FALSE` code: `impute_obj <- impute(draws_obj, references)` then `desc <- describe_imputation(impute_obj)` then `print(desc)`
- Include hand-formatted example output showing method, M, subjects, references table, missingness breakdown
- Explain the returned fields: method, n_imputations, n_subjects, references, missingness (data.frame with visit/arm/n_missing/n_total/pct_missing)

**Section 5: MI Diagnostic Statistics in ARD** (eval=TRUE)
- This section CAN be eval=TRUE because pool_to_ard() works with the analysis/pool objects from Section 2
- Explain that pool_to_ard() now accepts an optional analysis_obj parameter
- Show: `ard <- pool_to_ard(pool_obj)` (base ARD) vs `ard_enriched <- pool_to_ard(pool_obj, analysis_obj = ana_obj)` (enriched)
- Filter and display the diagnostic stats: `ard_enriched[ard_enriched$stat_name %in% c("fmi", "lambda", "riv", "df.adjusted", "re"), c("group1_level", "variable_level", "stat_name", "stat")]`
- Explain each diagnostic: FMI (fraction of missing information), lambda (proportion of variance due to missingness), RIV (relative increase in variance), df.adjusted (Barnard-Rubin adjusted degrees of freedom), re (relative efficiency)
- Guard the eval with `eval = requireNamespace("cards", quietly = TRUE)` on the chunk option

**Section 6: When Diagnostics Are Not Available** (~5 lines, no code)
- Note that non-Rubin pooling methods (condmean) do not produce MI diagnostics
- pool_to_ard() will emit an informative message and omit diagnostic rows
- describe_draws() and describe_imputation() work with all method types

**Section 7: Learn More** (~3 bullets)
- Link to pipeline vignette for the full end-to-end workflow
- Link to pool_to_ard() function documentation
- Link to describe_draws() and describe_imputation() function documentation
