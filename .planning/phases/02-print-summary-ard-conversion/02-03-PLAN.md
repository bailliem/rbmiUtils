**Step 2: Create R/ard_conversion.R** with the exported pool_to_ard() function:

```r
pool_to_ard <- function(pool_obj, conf.level = NULL)
```

**Function implementation:**

1. **Dependency check:** Use `requireNamespace("cards", quietly = TRUE)`. If cards not available, call `cli::cli_abort("Package {.pkg cards} is required for ARD conversion. Install with {.code install.packages('cards')}.", class = c("rbmiUtils_error_dependency", "rbmiUtils_error"))`.

2. **Input validation:** Check `inherits(pool_obj, "pool")`. If not, abort with `rbmiUtils_error_validation` class.

3. **Extract conf.level:** If conf.level argument is NULL, use `pool_obj$conf.level` (typically 0.95). If that is also NULL, default to 0.95.

4. **Tidy the pool object:** `tidy_df <- tidy_pool_obj(pool_obj)` to get the standard tidy tibble with columns: parameter, description, visit, parameter_type, lsm_type, est, se, lci, uci, pval.

5. **Build long-format ARD rows:** For each row in tidy_df, create 5 statistic rows (one per stat):
   - stat_names: c("estimate", "std.error", "conf.low", "conf.high", "p.value")
   - stat_labels: c("Estimate", "Std. Error", paste0(conf.level*100, "% CI Lower"), paste0(conf.level*100, "% CI Upper"), "p-value")

6. **Grouping columns per ARD-03:**
   - group1 = "visit", group1_level = visit value (list column)
   - group2 = "parameter_type", group2_level = parameter_type value (list column)
   - group3 = "lsm_type", group3_level = lsm_type value (list column, NA for trt rows)
   - variable = parameter name
   - variable_level = list(NA) for each row (continuous statistics, no variable levels)
   - context = "rbmi_pool"

7. **List columns (CRITICAL -- see Pitfall 2 and 3 in research):**
   - stat: MUST be list column. Use `I(list(r$est, r$se, r$lci, r$uci, r$pval))`
   - fmt_fun: list column. Use `I(as.list(rep(1L, n_stats)))` (integer formatting)
   - warning: list column. Use `I(as.list(rep(list(NULL), n_stats)))`
   - error: list column. Use `I(as.list(rep(list(NULL), n_stats)))`
   - group1_level, group2_level, group3_level, variable_level: ALL must be list columns

8. **Method row (optional but recommended per Pitfall 4):** Add one method row per unique variable with stat_name = "method", stat_label = "Method", stat = pool_obj$method (character). Same grouping columns as the parameter's other rows. This avoids the check_ard_structure() note.

9. **Assembly:** `do.call(rbind, rows)` then `cards::tidy_ard_column_order(cards::as_card(ard_df))`

10. **Return:** The resulting ARD data frame (class "card").

**Roxygen2 documentation:**
- @title Convert Pool Object to ARD Format
- @description Converts an rbmi pool object to the pharmaverse Analysis Results Dataset (ARD) standard using the cards package.
- @param pool_obj A pooled analysis object of class "pool"
- @param conf.level Confidence level for CI labels. Defaults to pool_obj$conf.level or 0.95.
- @return A data frame of class "card" (ARD format) with grouping columns for visit, parameter_type, and lsm_type.
- @seealso tidy_pool_obj, cards::as_card, cards::check_ard_structure
- @export
- @examples with \donttest{} showing basic conversion

**Anti-patterns to avoid:**
- Do NOT use atomic vectors for stat, fmt_fun, warning, error, or *_level columns. They MUST be list columns.
- Do NOT hardcode column order manually. Use cards::tidy_ard_column_order().
- Do NOT omit the requireNamespace guard. cards is Suggests, not Imports.
